# Implementation prompt: fully working OpenCode-style TUI for AI Editor

You are implementing a production-ready terminal user interface (TUI) for the **ai-editor** repository (`D:\ai` / repo root). The TUI must provide **full agentic coding parity** with the existing Tauri + React desktop app, with UX and interaction patterns aligned to **OpenCode** (terminal-first coding agent: project cwd, streaming chat, tool timeline, permissions, file edits with review, sessions, slash commands, model routing). Do not ship a thin HTTP demo; ship a **standalone headless binary** that runs without WebView.

**Constraints**
- Ship target: `ui/` + `src-tauri/` only. Do not extend legacy root `src/`.
- Do not add source code comments unless explicitly requested.
- Liquibase: if any DB migrations appear, use SQL changesets only.
- Update `docs/commands-and-events.md` and `docs/manual-test-script.md` for any new IPC, CLI flags, events, or TUI-only surfaces.
- Run `npm test` in `ui/` and `cargo test` in `src-tauri/` before considering done.
- Never commit secrets (HF tokens, API keys).

## 1. Product definition

### 1.1 Binary and entrypoints

Add a **second binary** in the workspace (preferred) or a feature-gated subcommand:

- **Name:** `ai-editor-tui` (or `ai-editor` with `ai-editor tui` subcommand via `clap`).
- **Invocation examples:**
  - `ai-editor-tui` — open TUI in current directory if git/workspace else prompt for path.
  - `ai-editor-tui --cwd C:\path\to\repo`
  - `ai-editor-tui --model path\to\model.gguf`
  - `ai-editor-tui --remote` — use Settings/providers route for `editor` role without GUI.
  - `AI_EDITOR_TUI=1` optional env mirror for CI smoke.

Release builds must **not** require port 1420 or embedded `dist/`; TUI uses Rust core only (`custom-protocol` irrelevant for TUI binary).

## 2. Architecture (mandatory refactor)

Today almost all logic is behind Tauri `AppHandle` + `emit`. The TUI **must not** spawn a hidden WebView. Extract a **headless application core** reused by Tauri `main.rs` and the TUI binary.

### 2.1 New module layout (under `src-tauri/`)

Create `src-tauri/src/core/` (or `src-tauri/src/app_core/`):

```
core/
  mod.rs
  runtime.rs      # AppCore: owns all managed state (mirror main.rs .manage(...))
  events.rs       # EventBus: typed enum AgentEvent + broadcast channel (tokio::sync::broadcast or crossbeam)
  dispatch.rs     # invoke-equivalent async API: run_agent_task, settings_load, ... (no Tauri)
  init.rs         # bootstrap logging, knowledge scan, default policy
```

**AppCore** holds:
- `InferenceState`, `ProviderRegistryState`, `ContextState`, `Arc<ToolState>`, `InterruptState`, `SearchIndex`, `WatcherState`, `KnowledgeState`, `LspManager`, `TerminalSessions`, `HubState`, `ApiServerState` (optional for TUI).

**Event emission:** Replace direct `app.emit("agent://...", payload)` in orchestrator/tools with `EventSink` trait:

```rust
pub trait EventSink: Send + Sync {
    fn emit(&self, event: &str, payload: Value);
}
```

Implementations:
- `TauriEventSink(AppHandle)` — existing behavior.
- `BusEventSink(Sender<CoreEvent>)` — TUI subscribes.

Refactor `orchestrator.rs`, `tools.rs`, `commands/agent.rs`, `engine` token path, `watcher`, `index` to accept `&dyn EventSink` or `Arc<dyn EventSink>` instead of hard-coded `AppHandle` where feasible. **Minimize duplication:** `run_agent_task_inner` must call the same code from TUI `dispatch::agent_run_task`.

### 2.2 TUI crate/binary

```
src-tauri/src/bin/ai_editor_tui.rs   # main: clap, crossterm, ratatui loop
src-tauri/src/tui/
  mod.rs
  app.rs           # TuiApp state machine
  ui/              # layout components
    chat.rs
    status_bar.rs
    tool_log.rs
    diff_review.rs
    permission_modal.rs
    question_modal.rs
    file_picker.rs
    session_sidebar.rs
  input.rs         # textarea + history (mirror console_history)
  stream.rs        # maps CoreEvent → UI mutations (port useAgentStream.ts)
  theme.rs
  markdown.rs      # lightweight terminal markdown
```

**Dependencies to add** (`src-tauri/Cargo.toml`):
- `ratatui` (with `crossterm` backend)
- `crossterm`
- `clap` (derive)
- `unicode-width`, `textwrap` (layout)
- Reuse existing: `serde_json`, `tokio`, `similar` (for TUI-side diff preview if needed)

### 2.3 Session / event filtering (port `useAgentStream.ts`)

Implement the same invariants:
- `activeSessionId`, `sessionClaimPending`, `sessionOwned` — ignore stale events from prior runs after `/new`.
- On send: `claimNextSession` → `prepareAgentTurn` → `context_push_turn(user)` → `agent_run_task` → `setActiveSessionId`.
- Filter all `agent://*` and `inference-token` / `inference-done` by `sessionId` when `sessionOwned`.
- On `inference-done`: append assistant turn via `session_append`; clear processing flag.
- Permission/question modals: single-flight; queue additional requests.

```json

  "maxTokens": 4096,

  "stopWords": [],

```

Build requests with same rules as `ui/src/lib/agentRequest.ts` `buildAgentRequest`.

**Prepare turn order** (critical):
1. Resolve workspace; `agent_set_workspace`
2. `context_set_system_prompt(buildSystemPrompt(mode, nParams))`
3. `buildContext` → `context_set_file_buffer`, attach images
4. `context_push_turn("user", userText)` last (evictable)
5. `agent_run_task(request)`

## 5. TUI layout and keybindings

### 5.1 Default layout (ratatui)

```
┌─ Sessions ─┬──────────────── Chat transcript ────────────────┬─ Tools ─┐
│  chat list │  user / assistant bubbles (scroll)              │ timeline│
│            │                                                  │ + todos │
├────────────┴──────────────────────────────────────────────────┴─────────┤
│ Composer (multiline)  [agent|ask|plan]  model:name  ctx:72%  cwd:...   │
└─────────────────────────────────────────────────────────────────────────┘
```

**Keys (OpenCode-like):**
- `Enter` — send (Shift+Enter newline)
- `Ctrl+C` — abort run if processing else quit
- `Ctrl+L` — clear screen / clear composer
- `Ctrl+O` — open diff review for pending edits
- `Ctrl+Y` / `Ctrl+N` — approve/deny permission when modal open
- `Tab` — cycle focus: chat / composer / side panel
- `Esc` — close modal; double-Esc → undo last turn (rewind)
- `?` — help overlay
- `Ctrl+P` — command palette (`:commands`)

### 5.2 Permission modal

Payload types from backend (mirror `PermissionRequest` in `ipc.ts`):
- Show tool name, args summary, category
- Decisions: `allow`, `allow_once`, `deny` → `agent_respond_permission(requestId, decision)`
- YOLO toggle in `:yolo on|off` → `agent_set_yolo`

### 5.3 Diff review modal

On `edit-proposed`:
- List files in group; selected file shows unified diff (scroll)
- `a` apply group, `r` reject, `o` overwrite on conflict (`agent_resolve_edit_conflict`)
- After apply, listen `edit-applied` / `verify-result`

### 5.4 Ask mode

When `currentMode === "ask"`: use `stream_inference` instead of `agent_run_task` if `preferChatComplete` setting true (read from settings); else `agent_run_task` with `agentMode: "ask"` and verify false.

## 7. Model load and startup sequence

1. Parse CLI args → resolve `cwd`
2. `logging::init` to app data logs dir (reuse `app_data_dir` helper extracted from Tauri path or `dirs` crate)
3. Construct `AppCore::new`
4. `settings_load` → `auto_load_model` or `providers_route("editor")` + `configure_remote_model`
5. `agent_set_workspace(cwd)` + `index_rebuild` async (show progress chip)
6. `knowledge_scan` optional background
7. Enter TUI main loop
8. On exit: `LspManager::shutdown_all`, unload model, flush sessions

**Smoke test:** `AI_EDITOR_TUI_SMOKE=1 ai-editor-tui --cwd . --no-model` exits 0 after init without curses if env set; or script driving `expect`/`script` in CI.
