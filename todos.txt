Backend (src-tauri)
Workspace index — Incremental file index (paths, hashes, optional embeddings stub); watch workspace://file-changed; expose index_status, index_search (text + ripgrep-style), index_semantic_search (optional hook for future embeddings).
Unified edit pipeline — propose_edits → structured FileEdit (path, range or full-file, patch/diff, reason); apply_edits (batch, atomic per file); reject_edits; persist pending edits per session.
Diff engine — Generate unified diffs; validate paths inside workspace + policy; conflict detection if file changed since read; return apply_result per file (success, conflict, denied).
Read model for agent — read_file / read_file_range with line numbers; search_code (index + ripgrep); list_dir with ignore (.gitignore); cap sizes; return citations {path, startLine, endLine} for UI chips.
Apply strategies — Support: (1) search-replace blocks, (2) unified patch, (3) whole-file write; single tool surface for LLM; normalize in orchestrator.
Composer vs agent modes — chat_complete (no tools, fast) vs agent_run (tools); shared context manager; mode in request envelope.
Inline / selection context — IPC: context_set_selection (path, range, text); pin in context manager; include in system sections.
Checkpoint / undo — Before apply_edits, snapshot file contents (session-scoped); checkpoint_list, checkpoint_restore (file or batch).
Review gate — Config: auto-apply vs require UI approval per edit batch; integrate with existing agent://permission-request and .ai/policy.json.
Terminal parity — Ensure terminal_spawn / terminal_write / agent://terminal-output stable; cwd = workspace; timeout + output truncation for agent consumption.
LSP hooks (optional phase 2) — lsp_diagnostics / lsp_definition stub or rust-analyzer bridge for “fix errors at path:line”.
Events — Emit agent://edit-proposed, agent://edit-applied, agent://edit-failed, agent://index-progress for UI.
Tests — Rust tests for patch apply, policy deny, conflict, checkpoint restore.
